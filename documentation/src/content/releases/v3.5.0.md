# v3.5.0: Optional parameter syntax and externally constrained names

`prefer-optional-parameter` adds a check for parameters typed with `undefined` unions. `starts-with-verb` and `require-async-suffix` now leave names alone when an externally imported type determines an object’s property names.

## 🚀 Added
- **prefer-optional-parameter**: Reports parameters such as `scenario: ScenarioId | undefined` and automatically rewrites them to `scenario?: ScenarioId` where TypeScript permits it; it reports without a fix when the parameter position cannot be made optional, such as before a required parameter or in an accessor setter - by @howmanysmall in [#93](https://github.com/howmanysmall/small-rules/pull/93)

## 🐞 Fixed
- **starts-with-verb**: Object-literal callback names constrained by an imported type annotation or type assertion, including through a local alias, no longer report. Names constrained only by local types still report - by @howmanysmall in [#92](https://github.com/howmanysmall/small-rules/pull/92)
- **require-async-suffix**: Async method names in object literals annotated with an imported type, including through a local alias, no longer report for missing the `Async` suffix; names constrained only by local types still report - by @howmanysmall in [#92](https://github.com/howmanysmall/small-rules/pull/92)
