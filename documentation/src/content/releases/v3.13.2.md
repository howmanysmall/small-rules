# v3.13.2: Restored reports and withheld unsafe autofixes

This release changes what `no-dead-store`, `no-recursive`, and `no-trivial-assertions` report, and withholds or corrects autofixes in several other rules. No option or config changes are needed to upgrade.

## 🐞 Fixed
- **no-array-constructor-elements**: The autofix is withheld when a push reads the array before the literal exists, such as `v.push(v.size());`. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **no-array-constructor-index-assignment**: The autofix is withheld when an assigned value or a moved statement reads the array early, such as `values[0] = (() => values.size())();`. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **no-async-in-system**: A reassigned `let` function is no longer checked as a system function, so `run` passes in `{ system: run }` after `run = () => {};`. Previously the first arrow reported. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **no-identity-map**: The autofix keeps parentheses around a receiver that binds looser than `.`, so `(flag ? first : second).map((item) => item).length` becomes `(flag ? first : second).length`. Previously the parentheses were dropped. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **no-instance-methods-without-this**: A method that uses `this` in a computed `accessor` key is no longer reported, so `return class { accessor [this.key] = 1; };` passes. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **no-print**: A `type` or `interface` named `print` no longer hides the global, so `print("a");` reports `noPrint` after `type print = string;`. Previously it was not reported. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **no-useless-constants**: The autofix is withheld when an assignment, `++`, `await`, `yield`, call, or tagged template runs before the reference, so `[counter++, LIMIT]` reports without a fix. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **no-useless-default**: The removal fix is withheld when the instance escapes through a declaration, nested block, `void` or `await` call, or spread call, so `configure(...[p]); p.Anchored = false;` reports without a fix. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **no-useless-default**: A property already written on the same instance is no longer reported, so `p.Anchored = true; p.Anchored = false;` passes. Previously the second write reported. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **no-warn**: A `type` or `interface` named `warn` no longer hides the global, so `warn("a");` reports `noWarn` after `type warn = string;`. Previously it was not reported. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **prefer-constant-dispatch**: The suggested constant is inserted after a leading `"use client"` directive. Previously it was inserted above the directive. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **prefer-membership-filter-in-jecs**: The autofix is withheld when a comment sits in the destructuring pattern or an empty `.with()` call, so `[entity, /* keep */ visual, transform]` reports without a fix. Previously the fix deleted the comment. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **prefer-modding-inspect**: The autofix is withheld for key types without a finite member list, such as `PropertyKey` or `Lowercase<string>`. Previously the rewrite lost the hand-written keys. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **prefer-sequence-overloads**: The autofix is withheld when a comment sits inside the call, so `new NumberSequence(0.5 /* start */, 0.5);` reports without a fix. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **prefer-single-world-query-in-jecs**: A `get` merge is withheld when a later component calls a function right away that reads an earlier variable, so `(() => first)()` reports without a fix. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **prefer-single-world-query-in-jecs**: A `has` merge is withheld when the block reads a global `hasAll`, so `if (hasA && hasB) { print(hasAll); }` reports without a fix. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **prefer-singular-enums**: `DBS`, `IDS`, `IPS`, `UIS`, and `VMS` with a trailing `S` count as plurals, so `enum IDS {}` reports. Previously it passed. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **require-safety-comment-for-type-assertion**: A `// SAFETY:` comment at the end of one statement no longer covers the next assertion, so `consume(raw as Foo);` after `const first = 1; // SAFETY: first is fine` reports. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **require-throw-error-capture**: The new error variable avoids names the block reads earlier, so `report(error);` before the throw produces `error2`. Previously the fix reused `error`, which put that read in its temporal dead zone. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **require-throw-error-capture**: The autofix is withheld when the throw comes before `super()` in a derived constructor, so `if (!ok) throw new Error("bad");` reports without a fix. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)

## 🔧 Changed
- **no-dead-store**: A write overwrites an earlier value across a fall-through only when no case on the way jumps out, so `case 1: v = 2; case 2: v = 3; return v;` now reports. Previously any fall-through counted as an overwrite. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **no-recursive**: Functions in one call cycle are reported together, including a cycle that reaches an already finished function, and calls between separate cycles are not. Previously the search missed some cycle members. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
- **no-trivial-assertions**: A deep comparison of a fresh value with a primitive constant now reports `freshIdentity`, so `assert.deepStrictEqual({}, 1);` reports. Previously it was skipped. - by @howmanysmall in [#132](https://github.com/howmanysmall/small-rules/pull/132)
