# v2.15.0: React effect anti-pattern rules

Version 2.15.0 adds nine React effect anti-pattern rules: `no-derived-state`, `no-initialize-state`, `no-pass-live-state-to-parent`, `no-chain-state-updates`, `no-adjust-state-on-prop-change`, `no-reset-all-state-on-prop-change`, `no-event-handler`, `no-external-store-subscription`, and `no-pass-data-to-parent`. It also updates `require-named-effect-functions` so its inline-function fix removes declarations that are no longer needed.

## 🚀 Added

- **no-derived-state**: Report effects that store values derived from props or state, such as `setFullName(`${firstName} ${lastName}`)`, and recommend computing the value during render - by @howmanysmall in [#40](https://github.com/howmanysmall/small-rules/pull/40)
- **no-initialize-state**: Report effects that initialize state on mount, including `useEffect(() => { setReady(true); }, [])`, and recommend passing the initial value to `useState()` instead - by @howmanysmall in [#40](https://github.com/howmanysmall/small-rules/pull/40)
- **no-pass-live-state-to-parent**: Report effects that pass live state values to a parent callback, and recommend lifting that state to the parent or returning it from a custom hook - by @howmanysmall in [#40](https://github.com/howmanysmall/small-rules/pull/40)
- **no-chain-state-updates**: Report effects that update state when another state value changes, such as an effect depending on `round` that calls `setIsGameOver`, so related state can be updated together - by @howmanysmall in [#40](https://github.com/howmanysmall/small-rules/pull/40)
- **no-adjust-state-on-prop-change**: Report effects that adjust state when a prop changes, such as `useEffect(() => { setSelection(undefined); }, [items])`, and recommend adjusting during render or restructuring the state - by @howmanysmall in [#40](https://github.com/howmanysmall/small-rules/pull/40)
- **no-reset-all-state-on-prop-change**: Report effects that reset every state value to its initial value when a prop changes, and recommend passing that prop as the component `key` - by @howmanysmall in [#40](https://github.com/howmanysmall/small-rules/pull/40)
- **no-event-handler**: Report effects that use state or props as an indirect event handler, such as an `if` condition inside an effect that triggers side-effecting code, and recommend calling the code directly from the event or moving it to the parent - by @howmanysmall in [#40](https://github.com/howmanysmall/small-rules/pull/40)
- **no-external-store-subscription**: Report effects that subscribe to an external store and update local state in the subscription callback, and recommend `useSyncExternalStore()` - by @howmanysmall in [#40](https://github.com/howmanysmall/small-rules/pull/40)
- **no-pass-data-to-parent**: Report effects that pass non-state data to a parent callback, and recommend fetching the data in the parent or returning it from a custom hook - by @howmanysmall in [#40](https://github.com/howmanysmall/small-rules/pull/40)

## 🔧 Changed

- **require-named-effect-functions**: When `inlineFunctionDeclarations: true` in standard or sloptor mode, remove a function declaration after inlining it only when it has one reference and is neither exported nor attached to comments. Multiple references, exports, and comments keep the declaration in place - by @howmanysmall in [#40](https://github.com/howmanysmall/small-rules/pull/40)
