# v2.4.1: Reliable allowFiles matching

`no-restricted-property-assignment` now applies `allowFiles` patterns consistently when Oxlint supplies an absolute filename. Patterns can match the file's path relative to the working directory as well as the absolute path, so existing allowlists such as `test/**/*.{ts,tsx}` suppress diagnostics in CI and editor runs alike.

## 🐞 Fixed

- **no-restricted-property-assignment**: Match `allowFiles` globs against both absolute and working-directory-relative filenames, so an assignment such as `_G.__DEV__ = true;` is suppressed for an absolute path like `/project/test/utils/development-flag.ts` when `allowFiles` contains `test/**/*.{ts,tsx}`. Basename patterns such as `development-flag.ts` continue to match - by @howmanysmall in [#13](https://github.com/howmanysmall/small-rules/pull/13)
