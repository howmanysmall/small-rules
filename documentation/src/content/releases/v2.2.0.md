# v2.2.0: Restricting writes and safer error captures

Version 2.2.0 adds `no-restricted-property-assignment` and fixes a false positive in `require-throw-error-capture`. The new rule reports configured property writes, while object-literal callbacks no longer receive invalid capture-stack-trace diagnostics or fixes.

## 🚀 Added

- **no-restricted-property-assignment**: Report assignments, compound assignments, and increment or decrement updates to configured properties, including computed properties by default; configure restrictions such as `{ "restrictions": [{ "object": "_G", "properties": ["__DEV__"] }] }`, with glob patterns, custom messages, and `allowFiles` exceptions - by @howmanysmall in [#10](https://github.com/howmanysmall/small-rules/pull/10)

## 🐞 Fixed

- **require-throw-error-capture**: Do not report anonymous function expressions or arrow functions used as object-literal properties, because a property key such as `load` or `validateAsync` is not a variable binding that can be passed to `Error.captureStackTrace` - by @howmanysmall in [#9](https://github.com/howmanysmall/small-rules/pull/9)
