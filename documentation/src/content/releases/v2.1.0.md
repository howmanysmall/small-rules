# v2.1.0: New recursion and array rules

Version 2.1.0 adds two rules and expands configuration for array appends, commented-out code, async naming, and error stack capture. It also removes false positives for imported type members and makes error-capture fixes safe inside catch blocks.

## ⚠️ Breaking Changes

- **require-throw-error-capture**: Change `allow` entries with `from: "lib"` to `from: "library"`; the old value is no longer accepted. File entries can now also set `path`, such as `{ from: "file", name: "ValidationError", path: "src/errors.ts" }` - by @howmanysmall in [#7](https://github.com/howmanysmall/small-rules/pull/7)

## 🚀 Added

- **no-array-constructor-index-assignment**: Report a zero-argument `new Array<T>()` followed by contiguous assignments starting at index `0`, and provide an autofix that produces an array literal, for example `const values = new Array<number>(); values[0] = 1;` becomes `const values = [1];` - by @howmanysmall [<samp>(17ad2)</samp>](https://github.com/howmanysmall/small-rules/commit/17ad2aa)
- **no-recursive**: Report each call site participating in direct or mutual recursion. The rule covers regular, async, generator, arrow-function, and class-method recursion, while ignoring calls to unresolved external callbacks - by @howmanysmall [<samp>(db9bf)</samp>](https://github.com/howmanysmall/small-rules/commit/db9bf7f)

## 🐞 Fixed

- **prevent-abbreviations**: Do not report imported member and qualified type names such as `MenuPrimitive.Root.Props`, including multi-level chains, when abbreviation checking is enabled - by @howmanysmall [<samp>(071c7)</samp>](https://github.com/howmanysmall/small-rules/commit/071c7e3)
- **require-throw-error-capture**: Generate a non-conflicting variable name when the throw is inside `catch (error)`, so the autofix uses `error2` instead of shadowing the catch parameter - by @howmanysmall in [#7](https://github.com/howmanysmall/small-rules/pull/7)

## 🔧 Changed

- **no-commented-code**: Add `maxLines` to suppress reports for commented-out code groups at or below the configured line count. For example, `{ "maxLines": 2 }` allows one- and two-line groups while three-line groups still report; the default `0` preserves the previous behavior - by @howmanysmall in [#6](https://github.com/howmanysmall/small-rules/pull/6)
- **no-array-size-assignment**: Add `environment: "standard"` to report `array[array.length] = value` and retain `array.push(value)` autofixes, while the default `"roblox-ts"` continues to check `array[array.size()] = value` - by @howmanysmall [<samp>(8f243)</samp>](https://github.com/howmanysmall/small-rules/commit/8f24343)
- **require-async-suffix**: Add an `except` array for async identifiers that may omit the `Async` suffix, and stop reporting async object-literal methods supplied as arguments to `CallExpression` or `NewExpression`, such as `Bun.serve({ async fetch() {} })` - by @howmanysmall in [#7](https://github.com/howmanysmall/small-rules/pull/7)
- **require-throw-error-capture**: Generate `Error.captureStackTrace(error, this.method)` for class methods, private methods, static methods, and arrow-function class fields instead of referring to the method as a bare identifier - by @howmanysmall in [#7](https://github.com/howmanysmall/small-rules/pull/7)
