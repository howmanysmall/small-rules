# v2.6.0: Class-aware Roblox yielding diagnostics

`no-async-in-system` now reports synchronous Planck systems that call Roblox APIs known to yield, rather than treating every `Async`-suffixed call as a violation. Detection follows Roblox service imports, `game.GetService(...)` results, typed receivers, and configured synchronous callbacks, while unrelated libraries and async callbacks remain unreported.

## 🔧 Changed

- **no-async-in-system**: Replace suffix-only matching with a class-aware Roblox yielding catalog, so calls such as `Players.GetFriendsAsync(userId)`, `player.IsFriendsWithAsync(userId)`, and `store.GetAsync("profile")` report when their receiver is known to be a yielding Roblox class - by @howmanysmall in [#17](https://github.com/howmanysmall/small-rules/pull/17)
- **no-async-in-system**: Recognize Roblox receivers imported from `@rbxts/services`, obtained through `game.GetService("Players")`, copied through `const` bindings, or declared with Roblox class types; calls from external libraries, shadowed names, and unrelated TypeScript types no longer report - by @howmanysmall [<samp>(67aef)</samp>](https://github.com/howmanysmall/small-rules/commit/67aef25)
- **no-async-in-system**: Inspect configured synchronous callbacks and inferred Roblox-typed callback parameters, while continuing to skip async callbacks, so yielding calls inside synchronous `world.added(...)` or `queue(...)` handlers are reported - by @howmanysmall in [#17](https://github.com/howmanysmall/small-rules/pull/17)
