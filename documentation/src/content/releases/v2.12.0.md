# v2.12.0: Fewer false positives across class and loop rules

Version 2.12.0 is a focused false-positive release for `no-dead-store`, `no-instance-methods-without-this`, and `require-async-suffix`. The updated rules account for loop iteration semantics, declaration-only methods, and names constrained by a base class.

## 🐞 Fixed

- **no-dead-store**: Treat compound assignments such as `count += 1` and `count -= 1` as reads of the previous value, so an earlier store is not reported as dead when the variable is updated this way - by @howmanysmall in [#32](https://github.com/howmanysmall/small-rules/pull/32)
- **no-dead-store**: Keep stores in a loop when the value can be read across iterations, including a value assigned in one iteration and consumed by a later iteration or by a loop step - by @howmanysmall in [#32](https://github.com/howmanysmall/small-rules/pull/32)
- **no-instance-methods-without-this**: Skip TypeScript overload signatures and abstract method declarations, which have no implementation body to inspect. A concrete overload implementation that does not use `this` continues to report - by @howmanysmall in [#33](https://github.com/howmanysmall/small-rules/pull/33)
- **require-async-suffix**: Skip async methods declared with `override` and async arrow-function or function-valued class fields declared with `override`, so inherited API names no longer require an `Async` suffix - by @howmanysmall in [#35](https://github.com/howmanysmall/small-rules/pull/35)
