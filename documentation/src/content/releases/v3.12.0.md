# v3.12.0: Enum assignment suppressions justify type assertions

One rule changed: `require-safety-comment-for-type-assertion` now accepts a described `typescript/no-unsafe-enum-assignment` suppression as justification for a type assertion, and a new `suppressionRules` option controls which rule IDs count.

## 🔧 Changed
- **require-safety-comment-for-type-assertion**: The rule now accepts a described `oxlint-disable-next-line` for `typescript/no-unsafe-enum-assignment` as justification for a type assertion, such as `const category = diagnostic.category as DiagnosticCategory;`, and the new `suppressionRules` option sets which rule IDs count, replacing the default pair. Previously only a described disable of `typescript/no-unsafe-type-assertion` counted, and the missing-comment message named only that rule. - by @howmanysmall in [#117](https://github.com/howmanysmall/small-rules/pull/117)
