# v2.8.0: New React import guidance and rule fixes

Version 2.8.0 adds `no-filter-map-chain` and the recommended `prefer-direct-hook-imports` rule, and fixes callback analysis and false positives in several existing rules.

## 🚀 Added

- **no-filter-map-chain**: Reports a direct `filter(...).map(...)` chain, including optional, computed, and wrapped calls, so the operations can be combined into one loop. The rule is available but disabled by default. - by @howmanysmall in [#23](https://github.com/howmanysmall/small-rules/pull/23)
- **prefer-direct-hook-imports**: Reports calls such as `React.useState(...)` and `React.useEffect(...)` when the hook comes from the configured React package, and supports `standard` or `roblox-ts` environments plus an `allowedHooks` exception list. Enable it with `"small-rules/prefer-direct-hook-imports": "error"`. - by @howmanysmall in [#23](https://github.com/howmanysmall/small-rules/pull/23)

## 🐞 Fixed

- **no-async-in-system**: Follow synchronous system functions that return a callback, whether the callback is inline or referenced by a variable, and optionally inspect callbacks passed to configured synchronous APIs through `synchronousCallbacks`. For example, configure `{ "synchronousCallbacks": [{ "calleePath": ["queue"], "callbackArgumentIndexes": [0] }] }` to inspect `queue(() => yieldingCall())`. - by @howmanysmall in [#19](https://github.com/howmanysmall/small-rules/pull/19)
- **no-render-helper-functions**: Do not report a render helper when its only use is as a callback argument such as `projects.map(renderItem)`, while still reporting a later direct call. - by @howmanysmall in [#23](https://github.com/howmanysmall/small-rules/pull/23)
- **prevent-abbreviations**: Do not report abbreviated properties in object arguments passed to functions imported from external packages, such as `useRender({ props: value })`, while continuing to check local and relative imports. - by @howmanysmall in [#23](https://github.com/howmanysmall/small-rules/pull/23)
- **require-async-suffix**: Do not require an `Async` suffix for async methods inside objects constrained with TypeScript `satisfies`, such as `const handler = { async fetch() {} } satisfies ExportedHandler<Env>`. - by @howmanysmall in [#23](https://github.com/howmanysmall/small-rules/pull/23)
