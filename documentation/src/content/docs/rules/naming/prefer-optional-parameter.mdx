---
title: "Prefer Optional Parameter"
---

import RulePage from "$components/rule-page.astro";

<RulePage rule="prefer-optional-parameter">
	<Fragment slot="rationale">
		<p>
			`scenario?: ScenarioId` and `scenario: ScenarioId | undefined` accept the same values. The first one names
			the intent: the caller may omit the argument. The second one still requires an argument, so `undefined`
			becomes a value the callee has to handle. It leaves the caller guessing whether the parameter is meant to be
			optional or whether `undefined` carries meaning.
		</p>
		<p>
			A default value and a rest parameter are already optional. The rule leaves them alone. It also leaves a
			parameter alone where TypeScript forbids the question mark: an optional parameter can't come before a
			required one, an accessor setter can't be optional at all, and a destructuring parameter can only be
			optional in a declaration signature, not in a function with a body. In those positions the union is the only
			valid way to accept `undefined`, so there is nothing to report.
		</p>
	</Fragment>
</RulePage>
