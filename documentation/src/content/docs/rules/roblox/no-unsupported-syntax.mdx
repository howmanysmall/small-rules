import RulePage from "$components/rule-page.astro";

<RulePage rule="no-unsupported-syntax">
	<Fragment slot="rationale">
		<p>
			This is a port from the official
			[roblox-ts ESLint plugin](https://github.com/roblox-ts/eslint-plugin-roblox-ts). It bans you
			from writing TypeScript that roblox-ts cannot turn into Luau, like `globalThis`, labeled
			statements, `.prototype`, regex literals, and (sometimes) rest elements in destructuring
			patterns all get flagged on by default.
		</p>
		<p>
			Every check is individually configurable, though, because not every Roblox-side compiler shares the same
			limits. The one that matters to me is `spreadDestructuring`: <strong>sloptor supports it</strong>, so running
			this rule with the default settings against sloptor code is wrong.
		</p>
		<p>This is valid with sloptor!</p>

```ts
const array = [1, 2, 3, 4, 5];
const [a, , ...rest] = array;
```

```luau
-- Compiled with sloptor v2.3.3
local array = { 1, 2, 3, 4, 5 }
local a = array[1]
local rest = table.move(array, 3, #array, 1, {})
return nil
```

    	<p>
    		Even the hole in the middle survives, the rest is `table.move`'d to a fresh table, starting after the skipped
    		element. If you're on sloptor, turn that check off:
    	</p>

```json
{
	"rules": {
		"small-rules/no-unsupported-syntax": ["error", { "spreadDestructuring": false }]
	}
}
```

    	<p>
    		The other four stay on. If your compiler ever grows support for one of them (somehow),
            toggle need to disable the whole rule.
    	</p>
    </Fragment>

</RulePage>
