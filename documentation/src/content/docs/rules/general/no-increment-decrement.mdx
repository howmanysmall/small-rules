---
title: "No Increment Decrement"
---

import RulePage from "$components/rule-page.astro";

<RulePage rule="no-increment-decrement">
	<Fragment slot="rationale">
		<p>This matches the reason Swift removed these operators in Swift 3.</p>
		<ul>
			<li>
				**Low utility relative to the readability loss:** these operators only save a few characters compared to
				`value += 1` or `value -= 1`. That trade is seldom useful.
			</li>
			<li>
				**Prefix vs postfix confusion:** having both `++value` and `value++` is confusing. It can also lead to
				fun subtle bugs, especially when you nest them inside larger expressions where evaluation order matters.
			</li>
			<li>
				**Redundancy:** the increment and decrement operators repeat what `+=` and `-=` already do. You can add
				or subtract any value, not just 1.
			</li>
			<li>
				**Clarity over brevity:** explicit code is the goal. Writing `value += 1` makes the intent immediately
				clear without requiring anyone to puzzle over operator precedence.
			</li>
		</ul>
		<p>
			Swift bans the operators outright. This rule still allows <code>array[size++] = value</code>. That form
			beats <code>array.push(value)</code> when the extra call costs too much, and the increment is a short spelling
			for that one case. The native Oxlint rule has no such exception.
		</p>
	</Fragment>
</RulePage>
