<RulePage rule="require-safety-comment-for-type-assertion">
	<Fragment slot="rationale">
		<p>
			Ported from <a href="https://github.com/dmmulroy/anti-slop">dmmulroy/anti-slop</a>. A cast is an unchecked
			claim. A nearby `SAFETY:` comment records the invariant that makes that claim legitimate; `as const` is
			exempt because it does not claim an unrelated runtime shape.
		</p>
		<p>
			I also count a described disable of `typescript/no-unsafe-type-assertion` as justification, because I don't
			want you to write the same sentence twice. That only works if the disable actually covers the diagnostic.
			`oxlint-tsgolint@7.0.2002` narrowed the report onto the `as Type` syntax, so a `disable-next-line` above a
			multi-line object is unused while the `as` still fails. Tell the rule which world you're in with{" "}
			<a href="/small-rules/configuration/#plugin-settings">`{'settings["small-rules"].tsgolintVersion'}`</a>. If
			you omit it, I look at `node_modules/oxlint-tsgolint`, then `pnpm-workspace.yaml` , then `package.json`.
		</p>
	</Fragment>
</RulePage>
